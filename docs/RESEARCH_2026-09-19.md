## 二、本次已修复（实测确认）

### ✅ P0-1 分享页口令解锁后整页白屏

- **现象**：客户打开分享链接 → 输入口令 → **白屏**，整条客户主线走不通。
- **实测证据**：
  ```
  React has detected a change in the order of Hooks called by SharePage
  Uncaught Error: Rendered more hooks than during the previous render.
  An error occurred in the <SharePage> component.
  ```
- **根因**：`SharePage.tsx` 有 4 处提前 `return`（口令页/错误页/加载页/访客名页），
  而 `useState` / `useEffect` / `useCallback` 写在这些 `return` **之后**。
  首次渲染走 return（hook 少），解锁后不走 return（hook 多）→ React 抛错。
- **修复**：把这 3 个 hook 提到所有 `return` 之前，并加注释说明为什么不能再挪回去。
- **验证**：修复后分享页正常渲染（canvas + 批注列表 + 「可批注」标识）。

### ✅ P0-2 `ReviewPanelHost` 跨域引用

- `features/viewer` 直接 import `features/review`，违反 `app → pages → features → shared` 单向依赖。
- **判断**：该组件职责是「批注面板外壳」（状态筛选、批注计数、折叠），本就是审稿域的东西，
  是被放错位置的 review 组件。
- **修复**：`git mv` 到 `features/review/components/`，域内走相对文件引用避免桶文件循环。
- **验证**：`npm run check:arch` **通过**（此前 1 项失败）。

### 产品口径（老板确认，2026-09-19）

| 约定 | 说明 |
|---|---|
| 本地上传的去向 | **只落浏览器 IndexedDB，绝不上传**。这是 `transport: "browser"` 的语义 |
| 上传的前提 | **必须有账号**。未登录时浏览器转换失败不会回退到本机 Blender / 云端——那等于在用户不知情下把原件送出去 |
| 永久分享链接 | **只针对内置猴头演示模型**（预览用途，不走 `createShare`） |
| 用户上传的模型 | **一律按设定权限与有效期**，默认 24h、上限 48h |
| 本地清理 | **不做**。自动清理只针对 CF 存储 |

### P1 — 状态与契约

**审稿 / 分享**
- **guest 轮询无代际守卫**：owner 侧有 `generation` 守卫，guest 侧直接 `setComments`，
  在途轮询晚于写响应返回会抹掉刚发的批注（`useGuestReview.ts:53`）。
- **`useReviewComments` updater 内副作用**：在 `setComments` 的 updater 里调 `setNewCount`、改 ref，
  StrictMode 下双执行（`:53-62`）。
- **空权限控件**：`BlenderWorkspace.tsx:1044` 让访客 `readOnly=false`，于是编辑框与「解决/重开」
  对客户可见，但 SharePage 没传 `onUpdateComment`，点了静默失效（UI 越权，无后端越权）。
- **降级创建的批注不落删除令牌**：自己发的也删不掉（`useGuestMutations.ts:69`）。
- **口令进 URL**：`SharePage.tsx:80` 读 `?pwd`，`:183-188` 自动解锁，留痕于历史与日志。
- **transport 仅凭 hostname 推断**：本地项目经 LAN/自定义域打开会打错后端（`SharePage.tsx:51-58`）。
- **批注编号取过滤后下标**：筛选/删除后序号漂移（`ReviewAnnotations.tsx:170`、`ReviewItem.tsx:44`）。

**工作区 / 视口**
- **模型显示被清单阻塞**：`workspaceModelUrl` 以 `manifest` 为前置，清单加载中/失败时
  `modelUrl` 变 `undefined`，视口退化成「打开 .blend」，而模型本身可用（`WorkspacePage.tsx:523-529`）。
- **选项目却弹出导入框**：`switchProject` 无条件 `setUploaderOpen(true)`（`:475`）。
- **错误提示被自动清掉**：`:256-260` 对 `reviewMessage` 无条件 4s 清除，含保存失败提示，
  与「错误常驻」的注释矛盾。
- **相机被面板拖拽重置**：预设 effect 依赖 `size.width/height`，拖右侧面板即重新 `frameScene`，
  用户视角被覆盖（`ViewControls.tsx:87`）。
- **批注选中卡片裸样式**：`ReviewAnnotations.tsx:138` 用 Tailwind 类，但项目无 Tailwind 配置/CDN。
- **ObjectOutliner 无虚拟滚动**：1000+ 对象时全量 map 渲染（`ObjectOutliner.tsx:90`）—— 注意文件里
  仍 import 了 `@tanstack/react-virtual` 但未启用。

**入口 / i18n**
- **平台状态无错误态**：catch 置 null 与初值同形，页面一律渲染「—」（`StartPage.tsx:377-460`）。
- **localStorage 写入无 try/catch**：隐私模式会抛错（`WorkspacePage.tsx:236/242/497`）。
- **i18n 多属性元素共用一个 WeakMap 且只备份首个**：切回中文后 `aria-label` 或 `placeholder`
  之一永久英文（`i18n/index.tsx:203-219`）。
- **已映射文本不再更新备份**：EN 下内容刷新后切回中文会还原旧值（`:190-201`）。
- **落地页字典缺键**：`demos.ts:176/209` 的「复制分享文本」、`StartPage.tsx:434` 的「累计处理」等。
- **落地页双视角 CTA 同指站点根**：注释称客户侧应进演示视口（`index.html:2661/2666`）。
- **落地页切语言不重载**：直接写 DOM 的 `stats.ts:46/74`、`tarot.ts:201` 不重译。
- **落地页 chip 组互斥过度**：快速上手②四个 chip 同属一组，选权限会清掉有效期选中（`cards.ts:239`）。

**后端一致性**
- **无本地限流**：`worker/rate-limit.ts` 全部规则 server 无对应，本地可无限试密码/刷批注。
- **错误码不一致**：访客回复失败本地 404 vs 云端 403；空 PATCH 本地 200 vs 云端 400。
- **分享名来源不一致**：本地取 `manifest.scene`，云端取项目名。
- **敏感路径**：`blendProofClient.ts:159-181` 不校验 bridge 必须 loopback，
  若 `VITE_LOCAL_BRIDGE_ORIGIN` 指向远端，原件真会出网（默认 vite proxy 下安全）。

## 五、需要老板决策的开放问题

1. **浏览器转换的项目要不要在本机 bridge 注册？**
   这是 P0-3/P0-4 的共同根因。两个方向：
   - **A**：转换成功后把产物上传到 bridge，登记成一个真正的 local 项目（链路统一，但「原件不出本机」的承诺要重新审视措辞——产物本来就要出本机）
   - **B**：浏览器转换的项目标记为 `demo`/`browser` transport，分享时自动改走 bridge 转换
   倾向 A，改动小且语义清楚。

2. **「分享永久有效」是不是有意的？**（P0-7）
   本地永不过期 vs 云端 48h 上限，是有意放宽还是遗漏？

3. **本地要不要实现定时清理？**（P0-8）
   产品对外承诺「48h 自动清理」，本地目前永久留存。
