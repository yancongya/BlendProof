# BlendProof 长期实施计划

## 目标与约束

BlendProof 是同一个 Web 应用中的本地导入、转换、审稿和只读分享流程：`.blend` 在本机 Blender 导出为 GLB，浏览器只处理 GLB 审稿与分享。

当前阶段不再继续从零模拟成熟 3D 浏览器的导航、相机和选择系统。每项交互先从 `temp/3D-Review-Research/` 中的参考实现确定边界与测试方式，再接入或抽取到产品。

## 已确定事实

- 导出脚本开启 `export_cameras=True`，GLB 含有文件相机。
- 现有“相机闪烁后复位”是自写 React Three Fiber 相机控制与场景居中变换之间的实现风险，不应再靠局部补丁延续。
- 参考目录是只读研究材料，不进入 BlendProof 主仓库历史，也不修改其源码。

## 阶段路线

### 阶段 0：研究基线与验收样例

状态：完成（2026-09-08）。

1. 固定参考仓库及对应职责。
2. 准备至少三组 GLB 验收样例：无相机、单相机且与默认视角差异明显、多相机。
3. 建立交互验收清单：相机切换不能闪回；空白取消选择；点击与框选；局部视图；线框、灰模、材质；中键旋转、Shift 加中键平移、滚轮缩放。
4. 为每一个通过项录制浏览器截图或自动化证据。

完成情况：三组 `.blend`、`.glb`、manifest 已由 `npm run create:viewer-fixtures` 可重复生成；浏览器失败边界和参考职责已记录在 `docs/VIEWER_BASELINE.md`。

### 阶段 1：替换 Viewer 内核

状态：未开始。

1. 以 Online3DViewer 的相机状态、导航模式、视图投影和模型装载逻辑为主参考。
2. 对照 glTF-Sample-Viewer 验证 GLB 相机、灯光和坐标系的正确读取。
3. 对照 BabylonJS / model-viewer 评估封装成本；只有在能降低核心交互风险时才替换底层，不并行维护多套 Viewer。
4. 将产品层限定为：Blender 风格外壳、上传/转换、Outliner、属性、审稿标记、分享权限。Viewer 内核负责相机、拾取、框选、渲染和导航。

完成条件：文件相机、正交/透视、点击选择、框选、局部视图在三组验收 GLB 中均无闪回。

### 阶段 2：审稿能力

状态：未开始。

1. 基于 Share 与 Open3DInspection 研究评论数据模型、标注锚点、只读审稿界面和项目状态。
2. 加入场景位置、法线/对象锚定、相机状态、文字评论和截图。
3. 保持上传页与 `/s/:token` 分享页使用同一 Viewer 组件，避免两套前端。

完成条件：创建者可以在本地项目中添加审稿意见，分享页可准确重放。

### 阶段 3：本地分享后端

状态：部分完成。

1. 继续使用本地 Express、文件存储和 manifest 作为开发合同。
2. 增加项目、分享令牌、密码、过期时间、评论的 SQLite 数据层。
3. 先以 `owner_id` 字段预留用户边界，不在 Viewer 基线稳定前接入完整账户系统。

完成条件：同一 Web 里完成 `.blend → GLB → 创建分享 → 另一浏览器打开 → 评论`。

### 阶段 4：云端替换

状态：未开始。

1. 保持 Storage 与数据库接口稳定。
2. 本地文件存储替换为 R2，本地 SQLite 替换为 D1，HTTP API 替换为 Workers。
3. 最后才加入实际账户、额度、自动过期删除与生产监控。

完成条件：不改 Viewer 与业务流程，只替换基础设施实现即可部署。

## 当前下一步

先停止为现有自写相机控制继续加功能。阅读 Online3DViewer 的相机、导航和选择实现，写出“直接复用/适配/不采用”的决策表；随后用一个相机明显不同的测试场景接入新的 Viewer 基线并做浏览器验收。
